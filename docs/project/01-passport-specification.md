# f(AI) Control — паспорт и ТЗ

## Назначение
Самостоятельно размещённый продукт для управления разработкой и коммерческими
проектами. Основа — Paperclip Core и штатный GUI; одно расширение fai-control
добавляет недостающие функции запуска проекта и интеграции Hermes.
Репозиторий: https://github.com/VF78/fai-control-plane.
Интерфейс: https://app.f-ai.studio.

## Запуск проекта
Владелец вручную проходит возобновляемый wizard: репозиторий → трекер/процесс →
документы → Hermes/доступы → команда/чаты → проверка → первая задача.
Сохранённые шаги можно открыть и исправить. Не должно требоваться поиска UUID,
ручного создания credential-файлов для каждого проекта или повторного ввода
одного общего GitHub-аккаунта.
GitHub repo и ветка обязательны до первого полезного запуска. Привязка
существующего repo и явное создание нового — разные действия. Branch, PR,
проверенный commit и ссылки на результат сохраняются с задачей.

## Документы
Паспорт и ТЗ обязательны; этот файл объединяет их. Архитектура загружается
отдельно; при отсутствии Hermes предлагает её владельцу. MD/TXT/DOCX/PDF,
оригиналы через штатное file API Core, компактный версионируемый контекст
со ссылками. Hermes получает актуальную версию без полного архива на каждый run.
Документы — справочные данные, а не разрешение на инструменты/production.

## Роли и разработка
Владелец задаёт приоритет, критерии приёмки и разрешения merge/deploy.
Один постоянный Hermes на проект: PM, координация Developer CLI, DevOps и чаты.
Developer — Codex CLI по проектной политике, без отдельного постоянного Hermes.
QA — отдельная project-specific native `codex_local` identity с независимым заключением по точному
commit. У каждого проекта свой QA-профиль,
без таймера и фонового расхода. QA может сам исправить только детерминированные
lint/format дефекты без изменения поведения, публичного текста или ожиданий тестов;
функциональные дефекты одним сводным отчётом возвращаются Developer.
Hermes/Developer и QA одного проекта используют один проектный Codex-login;
для каждого следующего проекта выполняется отдельная device-auth. Login,
лимит и Codex home между проектами не копируются и не наследуются.

Этапы: Backlog → Ready → Development → независимый Review → Owner Acceptance →
отдельно разрешённые Merge/Deploy → smoke и результат. Core управляет
статусами/review/approval; расширение не создаёт вторую машину состояний.
Участники и критерии сохраняются в native задаче; процесс редактируется через
native поля/политику. Универсальный отдельный process editor не нужен для пилота.
Один исполнитель одновременно; компактная задача и точный diff; Dev выполняет
релевантные проверки, QA проверяет риски и недостающее без слепого повтора
зелёных проверок. Повторные неуспешные циклы эскалируются владельцу.
При native `maxReviewRounds=2` допустим один автоматический цикл исправления;
второе отклонение передаётся ответственному человеку. Плагин эту политику не задаёт.
Лимит провайдера означает блокировку, а не успешную QA.

## Трекер
Целевая единственная рабочая доска — native задачи f(AI) Control.
GitHub сохраняет код, PR и историю. После ручного создания рабочего проекта
переносится один раз только актуальная незавершённая работа с исходными ссылками.
После зафиксированного cutover статусы этих задач в GitHub Project не обновляются.
Внешний Project-коннектор отложен; синхронизация двух досок не нужна.

## Доступы и чаты
Общий GitHub-аккаунт настраивается один раз у Core для разрешённых проектов.
Секреты не попадают в документы/бизнес-записи. Memory, sessions, workspace и
контекст каждого Hermes изолированы. SSH/DevOps разных клиентов выдаются отдельно.
Только внутренний Telegram для этого проекта. Клиентский канал не нужен.
Будущий коммерческий проект получит Element с отдельным ограниченным профилем:
без внутренних инструментов, контекста, секретов, deploy и approvals.
Транспорт и история чатов исключительно в Hermes. Статусы отправляются штатным
Hermes без второго bot/poller и LLM на каждое уведомление. IDs/секреты — в настройках.

## Приёмка
Владелец вручную проходит чистый wizard, затем одна простая реальная задача:
Hermes читает контекст и берёт работу → Dev создаёт полезный PR → независимый QA
проверяет точный commit → владелец принимает → отдельно одобренные merge/deploy
→ успешный smoke → статусы в Telegram. Перезапуск сохраняет идентичность,
контекст и доступ, не повторяет завершённую работу. До этого MVP не принят.
Не трогать MSA Hermes, маркетинговый сайт, VPN и чужие сервисы.
Удалять только доказанно заменённый код и тестовые ресурсы f(AI) Control.
Живой статус/решения находятся в единственном действующем трекере.
